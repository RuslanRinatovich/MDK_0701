# 🧪 Практическая работа №29  
## Создание плана: резервное копирование + перестроение индексов

⏱️ **Продолжительность:** 90 минут  
🎯 **Цель работы:**  
Научиться создавать и настраивать планы обслуживания в SQL Server Management Studio, включая задачи резервного копирования, перестроения индексов, обновления статистики и очистки старых файлов.

🖥️ **Оборудование:**  
Виртуальная машина с Windows Server / Windows 10, установленными SQL Server Developer Edition и SSMS.

## 🧠 Глубокое погружение: перед началом

Планы обслуживания — это самый простой способ автоматизации задач по обслуживанию баз данных. В этой работе вы создадите полноценный план обслуживания, который будет выполнять комплекс задач: проверку целостности, перестроение индексов, резервное копирование и очистку.

**В результате вы получите работающий план, который можно использовать на реальном сервере.**

## 📋 Ход выполнения работы

### 🔹 Этап 1. Подготовка среды и создание тестовой базы (10 мин)

1. Запустите **SSMS** и подключитесь к экземпляру SQL Server.

2. Убедитесь, что SQL Server Agent запущен.

3. Создайте тестовую базу данных с достаточным количеством данных:

```sql
CREATE DATABASE MaintenanceTest_Фамилия;
GO
USE MaintenanceTest_Фамилия;
GO

-- Таблица с большим количеством строк для демонстрации фрагментации
CREATE TABLE dbo.TestData (
    ID INT IDENTITY(1,1) PRIMARY KEY,
    Col1 INT,
    Col2 VARCHAR(100),
    Col3 DATETIME DEFAULT GETDATE(),
    Col4 CHAR(500) DEFAULT 'A'
);

-- Создаём дополнительный индекс для демонстрации
CREATE INDEX IX_TestData_Col1 ON dbo.TestData(Col1);
CREATE INDEX IX_TestData_Col2 ON dbo.TestData(Col2);

-- Заполняем данными (20 000 строк)
WITH Numbers AS (
    SELECT TOP 20000 ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS n
    FROM sys.objects a CROSS JOIN sys.objects b
)
INSERT INTO dbo.TestData (Col1, Col2)
SELECT 
    n,
    'Value_' + CAST(n AS VARCHAR)
FROM Numbers;

-- Создаём фрагментацию (обновление случайных строк)
UPDATE dbo.TestData SET Col2 = 'Updated' WHERE ID % 10 = 0;
UPDATE dbo.TestData SET Col2 = 'Modified' WHERE ID % 7 = 0;
GO
```

4. **Сделайте скриншот** создания базы данных.

### 🔹 Этап 2. Создание плана обслуживания (15 мин)

2.1. **Откройте мастер создания плана обслуживания:**

```
Management → Maintenance Plans → ПКМ → New Maintenance Plan...
```

2.2. **Назовите план:** `Maintenance_Фамилия`

2.3. **Настройте планировщик SSMS** (если он откроется).

2.4. **Добавьте задачу «Проверка целостности»:**
   - Перетащите задачу **Check Database Integrity Task** из панели инструментов
   - Дважды кликните на задаче
   - **Databases:** Выберите `MaintenanceTest_Фамилия`
   - **Include indexes:** ✅ Да
   - **Physical only:** ❌ Нет (полная проверка)
   - **OK**

2.5. **Добавьте соединение между задачами:**
   - Подключите успешное выполнение проверки к следующей задаче

2.6. **Сделайте скриншот** дизайнера плана с добавленной задачей.

### 🔹 Этап 3. Добавление задачи перестроения индексов (15 мин)

3.1. **Добавьте задачу «Rebuild Index Task»:**
   - Перетащите задачу **Rebuild Index Task**
   - Соедините её с успешным выполнением проверки целостности

3.2. **Настройте задачу:**
   - **Databases:** Выберите `MaintenanceTest_Фамилия`
   - **Объекты:** `Tables and Views`
   - **Тип операции:** `Rebuild indexes` (и можно добавить `Reorganize pages`)
   - **Степень заполнения (FILLFACTOR):** `100` (без резерва)
   - **Сортировка в tempdb:** ❌
   - **Сохранение индекса онлайн:** ❌ (Enterprise Edition недоступно)
   - **Включить дополнительные действия:** ✅ Обновить статистику после выполнения

3.3. **Сделайте скриншот** настроек задачи перестроения индексов.

### 🔹 Этап 4. Добавление задачи резервного копирования (15 мин)

4.1. **Добавьте задачу «Back Up Database Task»:**
   - Перетащите задачу **Back Up Database Task**
   - Соедините её с успешным выполнением перестроения индексов

4.2. **Настройте задачу:**
   - **Type:** `Full`
   - **Databases:** Выберите `MaintenanceTest_Фамилия`
   - **Destination folder:** `C:\Backup\ПР29\`
   - **Create a subfolder for each database:** ❌
   - **Backup file extension:** `bak`
   - **Verify backup integrity:** ✅
   - **Compress backup:** ✅
   - **Set backup compression:** `Compress backup`
   - **Timestamp:** ✅ (добавлять метку времени к имени файла)

4.3. **Сделайте скриншот** настроек задачи резервного копирования.

---

### 🔹 Этап 5. Добавление задач очистки (15 мин)

5.1. **Добавьте задачу «Maintenance Cleanup Task»:**
   - Перетащите задачу **Maintenance Cleanup Task**
   - Соедините её с успешным выполнением бэкапа

5.2. **Настройте очистку файлов:**
   - **Delete files based on:** `Age of file`
   - **Folder:** `C:\Backup\ПР29\`
   - **Filename extension:** `bak`
   - **Delete files older than:** `3` `Day(s)`
   - **Include first-level subfolders:** ❌

5.3. **Добавьте задачу «History Cleanup Task»:**
   - Перетащите задачу **History Cleanup Task**
   - Соедините с успешным выполнением очистки файлов

5.4. **Настройте очистку истории:**
   - **Remove historical data older than:** `4` `Week(s)`
   - **Backup and restore history:** ✅
   - **SQL Server Agent job history:** ✅
   - **Maintenance plan history:** ✅

5.5. **Сделайте скриншот** настроек очистки.

---

### 🔹 Этап 6. Настройка расписания и запуск (10 мин)

6.1. **Изменение имени подплана:**
   - В дизайнере плана кликните на подплан
   - В свойствах измените **Name** на `Weekly_Maintenance`

6.2. **Настройка расписания:**
   - Кликните на иконку календаря рядом с названием подплана
   - **Schedule type:** `Weekly` (еженедельно)
   - **Occurs every:** `1` `Week(s) on Sunday`
   - **Occurs once at:** `03:00:00`
   - **OK**

6.3. **Сохраните план:** `Ctrl+S` или кнопка Save

6.4. **Запустите план вручную для проверки:**

```sql
-- Найдите задание, созданное для плана
SELECT 
    j.name,
    j.description,
    j.enabled
FROM msdb.dbo.sysjobs j
WHERE j.name LIKE '%Maintenance_Фамилия%';

-- Запустите задание
EXEC msdb.dbo.sp_start_job @job_name = 'Maintenance_Фамилия.Subplan_1';
```

6.5. **Сделайте скриншот** окна расписания.

### 🔹 Этап 7. Проверка результатов (10 мин)

7.1. **Проверьте выполнение через T-SQL:**

```sql
-- История выполнения плана
SELECT 
    j.name AS PlanName,
    jh.run_date,
    jh.run_time,
    CASE jh.run_status
        WHEN 0 THEN '❌ Ошибка'
        WHEN 1 THEN '✅ Успех'
        WHEN 2 THEN '🔄 Повтор'
        WHEN 3 THEN '⏹️ Отменён'
        WHEN 4 THEN '⏳ Выполняется'
    END AS Status,
    jh.message
FROM msdb.dbo.sysjobs j
JOIN msdb.dbo.sysjobhistory jh ON j.job_id = jh.job_id
WHERE j.name LIKE '%Maintenance_Фамилия%'
ORDER BY jh.run_date DESC, jh.run_time DESC;
```

7.2. **Проверьте созданные резервные копии:**

```sql
-- Просмотр бэкапов
SELECT TOP 5 * FROM msdb.dbo.backupset WHERE database_name = 'MaintenanceTest_Фамилия' ORDER BY backup_start_date DESC;

-- Физические файлы
EXEC xp_cmdshell 'dir C:\Backup\ПР29\*.bak';
```

7.3. **Проверьте состояние индексов:**

```sql
USE MaintenanceTest_Фамилия;
GO
SELECT 
    t.name AS TableName,
    i.name AS IndexName,
    s.avg_fragmentation_in_percent,
    s.page_count,
    s.fragment_count
FROM sys.dm_db_index_physical_stats(DB_ID(), NULL, NULL, NULL, 'LIMITED') s
JOIN sys.tables t ON s.object_id = t.object_id
JOIN sys.indexes i ON s.object_id = i.object_id AND s.index_id = i.index_id
WHERE t.name = 'TestData';
```

7.4. **Сделайте скриншоты** результатов выполнения.

## 💡 Полезные советы

### Если план не создаётся:
- Убедитесь, что SQL Server Agent запущен
- Проверьте, что у вас есть права sysadmin
