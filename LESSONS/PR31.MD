# 🧪 Практическая работа №31  
## Анализ блокировок и долгих запросов

⏱️ **Продолжительность:** 90 минут  
🎯 **Цель работы:**  
Научиться выявлять и анализировать блокировки, долгие запросы и ресурсоёмкие процессы с помощью Диспетчера активности и T-SQL, а также принимать меры по устранению проблем производительности.

🖥️ **Оборудование:**  
Виртуальная машина с Windows Server / Windows 10, установленными SQL Server Developer Edition и SSMS.

---

## 🧠 Глубокое погружение: перед началом

В этой работе вы создадите искусственные блокировки и долгие запросы, научитесь их обнаруживать и анализировать. Понимание механизмов блокировок критически важно для администратора баз данных.

---

## 📋 Ход выполнения работы

### 🔹 Этап 1. Подготовка среды (10 мин)

1. Запустите **SSMS** и подключитесь к экземпляру.

2. Создайте тестовую базу и таблицы:

```sql
CREATE DATABASE BlockingTest_Фамилия;
GO
USE BlockingTest_Фамилия;
GO

CREATE TABLE dbo.Accounts (
    AccountID INT IDENTITY(1,1) PRIMARY KEY,
    AccountNumber NVARCHAR(20),
    Balance DECIMAL(18,2)
);

CREATE TABLE dbo.Transactions (
    TransactionID INT IDENTITY(1,1) PRIMARY KEY,
    AccountID INT,
    Amount DECIMAL(18,2),
    TransactionDate DATETIME DEFAULT GETDATE()
);

-- Добавим начальные данные (10 000 строк)
WITH Numbers AS (
    SELECT TOP 10000 ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS n
    FROM sys.objects a CROSS JOIN sys.objects b
)
INSERT INTO dbo.Accounts (AccountNumber, Balance)
SELECT 
    'ACC' + CAST(n AS NVARCHAR(10)),
    10000 + (n % 5000)
FROM Numbers;

INSERT INTO dbo.Transactions (AccountID, Amount)
SELECT TOP 5000
    1 + ABS(CHECKSUM(NEWID())) % 10000,
    ROUND(RAND(CHECKSUM(NEWID())) * 1000, 2)
FROM sys.objects a CROSS JOIN sys.objects b;
```

3. Создайте некластеризованный индекс для ускорения запросов:

```sql
CREATE INDEX IX_Accounts_Balance ON dbo.Accounts(Balance);
```

4. **Сделайте скриншот** создания базы и таблиц.

---

### 🔹 Этап 2. Знакомство с Диспетчером активности (10 мин)

2.1. Откройте **Диспетчер активности**:
   - В обозревателе объектов ПКМ на сервере → **Activity Monitor**
   - Или нажмите `Ctrl+Alt+A`

2.2. Изучите вкладки:
   - **Обзор** (графики: CPU, ожидающие задачи, I/O, запросы/с)
   - **Процессы** (список сессий)
   - **Ожидания ресурсов** (группировка ожиданий)
   - **Последние ресурсоёмкие запросы** (история)
   - **Активные ресурсоёмкие запросы** (текущие долгие)

2.3. **Сделайте скриншот** окна Диспетчера активности с открытой вкладкой «Процессы».

---

### 🔹 Этап 3. Создание долгого запроса и его анализ (20 мин)

3.1. Откройте **новое окно запроса** (второе соединение). Назовём его **Сессия A**.

3.2. Выполните в нём долгий запрос:

```sql
USE BlockingTest_Фамилия;
GO
WAITFOR DELAY '00:00:30';  -- пауза, чтобы запрос был виден
SELECT 
    AccountID,
    AccountNumber,
    Balance,
    (SELECT COUNT(*) FROM dbo.Transactions t WHERE t.AccountID = a.AccountID) AS TxCount
FROM dbo.Accounts a
ORDER BY Balance DESC;
```

3.3. Пока этот запрос выполняется, в **основной сессии** (SSMS) откройте Диспетчер активности. Найдите строку с вашим долгим запросом (можно по имени базы или по приложению).

3.4. **Запишите** следующие данные из вкладки «Процессы» для этой сессии:
   - SPID
   - Команда
   - Длительность (мс)
   - Время ЦП (мс)
   - Физические операции чтения
   - Логические операции чтения

3.5. **Просмотрите текст запроса** через контекстное меню сессии в Диспетчере активности → **Details**.

3.6. **Сделайте скриншот** строки вашего долгого запроса в Диспетчере активности.

3.7. Дождитесь завершения запроса или прервите его (если надоело ждать).

---

### 🔹 Этап 4. Моделирование и анализ блокировок (25 мин)

4.1. Создайте **две дополнительные сессии** (вкладки «Новый запрос»): **Сессия B** и **Сессия C**.

4.2. **В сессии B** выполните транзакцию, которая обновит данные, но не закоммитит:

```sql
USE BlockingTest_Фамилия;
GO
BEGIN TRANSACTION;
UPDATE dbo.Accounts 
SET Balance = Balance - 100
WHERE AccountID = 1;
-- НЕ делайте COMMIT или ROLLBACK!
```

4.3. **В сессии C** попытайтесь выполнить запрос, который читает те же данные:

```sql
USE BlockingTest_Фамилия;
GO
SELECT * FROM dbo.Accounts WHERE AccountID = 1;
```

Этот запрос будет **заблокирован**, так как сессия B удерживает исключительную блокировку.

4.4. В **основной сессии** откройте Диспетчер активности. Найдите:
   - Сессию B — блокирующую (скорее всего, её SPID)
   - Сессию C — заблокированную (в колонке «Заблокировано» будет указан SPID блокировщика)

4.5. **Сделайте скриншот** вкладки «Процессы», где видны блокирующая и заблокированная сессии.

4.6. Выполните в основной сессии T-SQL запрос для анализа блокировок:

```sql
SELECT 
    blocking.session_id AS BlockingSPID,
    blocked.session_id AS BlockedSPID,
    blocked.wait_type,
    blocked.wait_time,
    blocked.wait_resource,
    blocked.command,
    (SELECT TEXT FROM sys.dm_exec_sql_text(blocked.sql_handle)) AS BlockedText,
    (SELECT TEXT FROM sys.dm_exec_sql_text(blocking.sql_handle)) AS BlockingText
FROM sys.dm_exec_requests blocked
JOIN sys.dm_exec_requests blocking ON blocked.blocking_session_id = blocking.session_id
WHERE blocked.blocking_session_id > 0;
```

4.7. **Запишите** результаты.

4.8. **Завершите блокировку** — в сессии B выполните:

```sql
COMMIT TRANSACTION;
```

4.9. Убедитесь, что сессия C разблокировалась.

4.10. **Сделайте скриншот** результатов T-SQL запроса к `dm_exec_requests`.

### 🔹 Этап 5. Поиск взаимоблокировки (Deadlock) (15 мин)

5.1. В **сессии B** выполните:

```sql
USE BlockingTest_Фамилия;
GO
BEGIN TRANSACTION;
UPDATE dbo.Accounts SET Balance = Balance + 50 WHERE AccountID = 1;
WAITFOR DELAY '00:00:05';
UPDATE dbo.Transactions SET Amount = Amount * 1.1 WHERE AccountID = 2;
COMMIT TRANSACTION;
```

5.2. В **сессии C** (одновременно с сессией B) выполните:

```sql
USE BlockingTest_Фамилия;
GO
BEGIN TRANSACTION;
UPDATE dbo.Transactions SET Amount = Amount * 0.9 WHERE AccountID = 2;
WAITFOR DELAY '00:00:05';
UPDATE dbo.Accounts SET Balance = Balance - 10 WHERE AccountID = 1;
COMMIT TRANSACTION;
```

При правильной синхронизации (если запустить их почти одновременно) возникнет взаимоблокировка, SQL Server выберет жертву.

5.3. В **основной сессии** проверьте журнал ошибок на наличие сообщения 1205:

```sql
EXEC xp_readerrorlog 0, 1, 'deadlock', '1205';
```

5.4. **Сделайте скриншот** сообщения о взаимоблокировке (если оно появилось). Если нет, можно создать более явную взаимоблокировку с помощью `WAITFOR DELAY`.

5.5. Если взаимоблокировка не возникла, можно использовать график взаимоблокировок из расширенных событий:

```sql
SELECT TOP 1 
    CAST(target_data AS XML).value('(RingBufferTarget/event[@name="xml_deadlock_report"]/data/value)[1]', 'NVARCHAR(MAX)') AS DeadlockGraph
FROM sys.dm_xe_session_targets
WHERE target_name = 'ring_buffer';
```

### 🔹 Этап 6. Анализ статистики ожиданий и диагностика (10 мин)

6.1. Получите глобальную статистику ожиданий (топ 10):

```sql
SELECT TOP 10
    wait_type,
    waiting_tasks_count,
    wait_time_ms,
    max_wait_time_ms,
    signal_wait_time_ms
FROM sys.dm_os_wait_stats
WHERE wait_type NOT IN ('BROKER_EVENTHANDLER', 'BROKER_RECEIVE_WAITFOR', 'BROKER_TASK_STOP', 'BROKER_TO_FLUSH', 'BROKER_TRANSMITTER', 'CHECKPOINT_QUEUE', 'CHKPT', 'CLR_AUTO_EVENT', 'CLR_MANUAL_EVENT', 'CLR_SEMAPHORE', 'DBMIRROR_DBM_EVENT', 'DBMIRROR_EVENTS_QUEUE', 'DBMIRROR_WORKER_QUEUE', 'DBMIRRORING_CMD', 'DIRTY_PAGE_POLL', 'DISPATCHER_QUEUE_SEMAPHORE', 'EXECSYNC', 'FSAGENT', 'FT_IFTS_SCHEDULER_IDLE_WAIT', 'FT_IFTSHC_MUTEX', 'HADR_CLUSAPI_CALL', 'HADR_FILESTREAM_IOMGR_IOCOMPLETION', 'HADR_LOGCAPTURE_WAIT', 'HADR_NOTIFICATION_DEQUEUE', 'HADR_TIMER_TASK', 'HADR_WORK_QUEUE', 'KSOURCE_WAKEUP', 'LAZYWRITER_SLEEP', 'LOGMGR_QUEUE', 'MEMORY_ALLOCATION_EXT', 'ONDEMAND_TASK_QUEUE', 'PREEMPTIVE_OS_LIBRARYOPS', 'PREEMPTIVE_OS_COMOPS', 'PREEMPTIVE_OS_CRYPTOPS', 'PREEMPTIVE_OS_PIPEOPS', 'PREEMPTIVE_OS_AUTHENTICATIONOPS', 'PREEMPTIVE_OS_GENERICOPS', 'PREEMPTIVE_OS_VERIFYTRUST', 'PREEMPTIVE_OS_FILEOPS', 'PREEMPTIVE_OS_DEVICEOPS', 'PREEMPTIVE_OS_QUERYREGISTRY', 'PREEMPTIVE_OS_WRITEFILE', 'PREEMPTIVE_XE_CALLBACKEXECUTE', 'PREEMPTIVE_XE_DISPATCHER', 'PREEMPTIVE_XE_GETTARGETSTATE', 'PREEMPTIVE_XE_SESSIONCOMMIT', 'PREEMPTIVE_XE_TARGETINIT', 'PREEMPTIVE_XE_TARGETFINALIZE', 'PWAIT_ALL_COMPONENTS_INITIALIZED', 'PWAIT_DIRECTLOGCONSUMER_GETNEXT', 'QDS_PERSIST_TASK_MAIN_LOOP_SLEEP', 'QDS_ASYNC_QUEUE', 'QDS_CLEANUP_STALE_QUERIES_TASK_MAIN_LOOP_SLEEP', 'REQUEST_FOR_DEADLOCK_SEARCH', 'RESOURCE_QUEUE', 'SERVER_IDLE_CHECK', 'SLEEP_BPOOL_FLUSH', 'SLEEP_DBSTARTUP', 'SLEEP_DCOMSTARTUP', 'SLEEP_MASTERDBREADY', 'SLEEP_MASTERMDREADY', 'SLEEP_MASTERUPGRADED', 'SLEEP_MSDBSTARTUP', 'SLEEP_SYSTEMTASK', 'SLEEP_TASK', 'SLEEP_TEMPDBSTARTUP', 'SNI_HTTP_ACCEPT', 'SP_SERVER_DIAGNOSTICS_SLEEP', 'SQLTRACE_BUFFER_FLUSH', 'SQLTRACE_INCREMENTAL_FLUSH_SLEEP', 'SQLTRACE_WAIT_ENTRIES', 'WAIT_FOR_RESULTS', 'WAITFOR', 'WAITFOR_TASKSHUTDOWN', 'WAIT_XTP_RECOVERY', 'WAIT_XTP_HOST_WAIT', 'WAIT_XTP_OFFLINE_CKPT_NEW_LOG', 'WAIT_XTP_CKPT_CLOSE', 'XE_DISPATCHER_JOIN', 'XE_DISPATCHER_WAIT', 'XE_TIMER_EVENT')
ORDER BY wait_time_ms DESC;
```

6.2. Обратите внимание на возможные `PAGEIOLATCH_*` или `LCK_M_*` ожидания.

6.3. **Сбросьте статистику** (опционально):

```sql
DBCC SQLPERF('sys.dm_os_wait_stats', CLEAR);
```

6.4. **Сделайте скриншот** топ-5 ожиданий.

## 💡 Полезные советы

### Для ускорения выполнения:
- При создании взаимоблокировки используйте `WAITFOR DELAY` с небольшими значениями (1-2 секунды).
- Если блокировка не возникает, попробуйте изменить порядок обновления таблиц.

### Для анализа deadlock:
- Включите трассировку флагов 1204, 1222 для записи информации о взаимоблокировках в журнал ошибок.

```sql
DBCC TRACEON (1204, 1222, -1);
```
